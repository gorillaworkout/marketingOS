# CS Report — implementation plan

Spec: `docs/superpowers/specs/2026-11-24-cs-report-design.md`. Branch `feat/cs-report` from `origin/main`.

## Tasks

1. **Access** — `CS_REPORT_FEATURE = 'cs-report'` in `src/lib/authorization.ts` (ACCOUNT_FEATURES, labels, href,
   prefix-matched). Sidebar section "Customer Service" in `src/app/dashboard/layout.tsx`.
   Tests: `tests/cs-report-access.test.ts` (feature, path gate, nav, every API route calls requireFeature).
   Update older migration tests that list every feature (057, 041/SEO, 066) to exclude `cs-report`.
2. **Migration 069 + rollback** — `db/migrations/069_cs_report.sql`, `db/rollbacks/069_cs_report_down.sql`.
   No `?` in SQL. Tests: static checks + PostgreSQL test (`tests/cs-report-pg.test.ts`, skipped without a URL)
   applying 069 twice, store round-trip, rollback.
3. **Pure core** (`src/lib/cs-report/`)
   - `types.ts`, `fields.ts` (column definitions shared by form, parser, export), `dates.ts` (WIB today, ranges,
     week/month bounds), `validate.ts` (daily entry + complaint input), `leave.ts` (fill colour → status),
     `dedupe.ts` (complaint key, name normalisation), `metrics.ts` (dashboard aggregation),
     `parse.ts` (ExcelJS workbook → entries / complaints / notes / warnings / per-sheet counts),
     `mapping.ts` (Excel name → agent/user suggestion), `export.ts` (ExcelJS workbook in the current layout).
   - Tests with a synthetic workbook built in the test (`tests/cs-report-parse.test.ts`), metrics, validation,
     export round-trip (export → parse gives the same rows).
4. **Store + service** — `store.ts` (SQL), `service.ts` (upload preview/commit, dashboard data, export).
5. **API** — `src/app/api/cs-report/`: `entries` (GET/PUT), `complaints` (POST), `complaints/[id]` (PATCH/DELETE),
   `dashboard` (GET), `agents` (GET), `upload` (POST preview/commit), `uploads` (GET history), `export` (GET).
6. **UI** — `src/app/dashboard/cs-report/page.tsx` (server access check) + `src/components/cs-report/*` client
   tabs: Dashboard, Daily Input, Bulk Upload.
7. **Verify** — `npm run lint`, `npx tsc --noEmit`, `npx tsx --test tests/*.test.ts` (with a local disposable
   Postgres for the -pg tests), `npm run build`; local parse of the real sample workbook printing counts only.
8. **PR** — description with migration/rollback and the post-release import steps.

## After release: importing the 12 historical sheets

1. Admin: Accounts → Departments → assign the CS agents to **Customer Service** (or add `cs-report` to their
   department).
2. Open **Customer Service → CS Report → Bulk Upload**, choose the workbook, check the preview (per-sheet counts,
   warnings such as the July block date fix), map each Excel name to the agent's account, then **Import**.
3. Uploading the same workbook again inserts nothing (all rows reported as already stored).
